# Changelog

## [Unreleased]

### Added
- **Dual continuous-time EMAs on the TPS ring.** Output now carries a fast (~0.8s) and a slow (~4s) tau with `alpha = 1 − exp(−dt/τ)`, so the smoothed rate weights real elapsed time instead of sample count — sparse and dense streams no longer skew differently. Input got the same time-weighted smoothing (`ema` column in `/tps`).
- **`/tps` overlay sparkline.** Output-rate history bucketed per ~500ms renders as a `spark ▁▂▃▅…` line; the shared `usageSparkline` moved into `src/usage/sparkline.ts` for reuse.
- **`powerline.workingVibes.color` styles the rotating vibe messages.** Upstream parity (nicobailon/pi-powerline-footer #173): set it to a Pi theme color (`accent`, `warning`, …), a `#RRGGBB` hex, or `rainbow` and every "Channeling {theme}..." placeholder, generated vibe, and file-mode fallback is painted through the session theme; omit it to keep Pi's default muted look. Exposed in the settings deck under Welcome & vibes.
- **`customItems[].selfColorize` trusts ANSI colors embedded in a status value.** Upstream parity (#176): an item with `selfColorize: true` skips the configured `color` wrap and keeps the producer's own escapes — including a trailing reset — so extensions that already paint their status text render exactly as emitted.
- **Session segment shows the session display name** when one is set (falls back to the short id), and refreshes on `session_info_changed` — renames are visible immediately.
- **Ctrl+S stashes or restores the draft** alongside Alt+S while the editor has focus (selector overlays keep their own Ctrl+S meaning).
- **Per-turn TTFT timing**: the turn clock now also arms on `turn_start`, so turns after the first no longer divide by turn-1's start.

### Fixed
- **Post-compaction context estimate.** When Pi reports `tokens: null` right after a compaction (or on a reloaded session), `context_pct` used to show stale pre-compact numbers or drop to 0 — it now estimates the rebuilt context from the active branch and shows `~x%` (`~12k/200k`), falling back to `?` when no estimate is possible. The estimate clears the moment real tokens return. `session_before_compact` additionally clears stale streaming/live-usage state so a mid-turn overflow compaction can't freeze the display.
- **Studio advice streams are actually cancelled.** Runs once had no abort controller, so closing Studio or starting a second request left the first one burning tokens; a shared run-owned controller is aborted on studio close and on session shutdown, and the pane's run counter now also covers the error path so a superseded stream can't write chunks, verdicts or failures over the pane's fresh state.
- **Session names are sanitized before the status bar.** A `session_info_changed` name carrying control characters or ANSI escapes could corrupt the powerline; the session segment strips them before render.
- **Session shutdown resets the vibe manager**: in-flight generation is aborted, `isStreaming` cleared and the stale extension ctx released instead of leaking into the next session.

### Changed
- **Shared text/numeric helpers canonicalized.** `stripAnsi`, `formatTokens`, `editDistanceWithin` now live in `src/tools/text.ts`; `clamp`/`clamp01` in `src/tools/num.ts`. `isRecord` has one canonical home in `config/primitives.ts` — `settings-io`'s copy dropped and seven importers repointed; private copies in hooks and working-vibes deleted (the standalone `queue/` boundary keeps its own).
- **Motion ticks no longer re-render every segment.** `renderStatusLineV2` is split into `buildStatusLineParts` + `composeStatusLine`; a painted tick now sets `rt.railDirty` and recomposes only the Signal rail with cached segment parts (~13× less per-tick compute, and no idle-time git/ports/command subprocess churn). Side effect: `time`, `time_spent`, git and command segments refresh only on real invalidations while idle — same behavior `off`/`reduced` motion already had.
- **Structural splits along existing seams.** `presets.ts` → `preset-table.ts` (data) + `presets.ts` (resolver + re-export). `config-cli.ts` (722 lines) → `config-cli-read/write/complete.ts` lanes + a facade runner. `skill-manager.ts` (551 lines) → `skill-manager-utils/-view/-input.ts` lanes around a shared `SkillManagerViewState`, with the manager staying the public face (re-exports preserved for tests).
- **The queue inbox is no longer re-read and re-parsed on every status paint.** `PowerlineQueueStore.list()` now memoizes the parsed inbox keyed on the file's mtime+size, so the two `summarize` calls each frame (segment context + queue preview row) cost a `stat` instead of a `readFileSync` + JSONL parse; store writes invalidate the entry, and cross-process appends show up on the next paint. Measured hot-path cost of `buildSegmentContext`'s queue read drops ~65%.
- **CI now enforces the ~450-line module-size convention, and maps boundary debt instead of letting it regrow.** Two new `test.yml` lanes join the `verify` aggregator. `bun run file-size` (`scripts/check-file-size.mjs`) fails when a tracked `.ts` source under `src/`, `bash-mode/` or `queue/` exceeds 450 lines, so no new oversized module can land; the 15 files already over the limit sit on an explicit grandfather list where each entry records its measured size — growth >10% past the baseline fails, and a completed split makes the entry stale until it is removed, the same describe-reality discipline as `audit-baseline.json`. `bun run boundaries` (`scripts/check-boundaries.mjs`) re-measures the four leaf-edge violation classes from the wave-2 architecture inventory — extension leaf→leaf, hub→leaf, standalone→src, and src→extension-leaf — printing every edge with `file:line` evidence grouped by leaf pair against the @c039639 baseline; it is informational by design while the debt is paid down, and `bun run circular` (madge) remains the acyclic gate.
- **Session usage now bills the whole session file, not just the active branch.** Tokens and dollars spent on a forked or abandoned sibling branch (`/tree` navigation, session forks) still hit the provider, but the status line only summed `getBranch()` — a rewind could silently drop real spend from `token_*`/`cost`, the `/usage` session column and the cost alert. The new `SessionUsageCache` sums `getEntries()` for the totals while `lastAssistant` and `thinkingLevelFromSession` stay on the active branch, matching upstream's "bill the full ledger, keep context on the branch" split. `session_tree` now also resets the ledger snapshot so SDKs without `getEntryCount()` notice entries appended off the active leaf.
- **`wishcraft-usage.json` records billed usage, not assistant-request usage.** The day file was written per `message_end` for non-error assistant messages only, so billed error/abort turns, toolResult native usage, `usage` entries (cache warming), compaction and branch-summary LLM calls — and all subagent child cost — never reached the daily budget or the `/usage` today/week columns. Instead of duplicating the ledger's shape rules at the event layer (where `usage` entries have no event at all), each session boundary now appends the *delta* of the same `SessionTokenStats` the bar displays — whatever the ledger bills, the file bills. The first flush per session only adopts a baseline, so resumed sessions never dump history into today, and a regressing total re-baselines rather than recording negative spend.

## [1.26.0] - 2026-11-12

### Removed
- **15 dead exports** (~230 lines, three files): `signal-layout.ts`, `welcome/widgets/index.ts` and the never-wired `welcome/widgets/graph-widget.ts` are gone entirely; `computeResponsiveLayout` (+`buildContentFromParts`), `showPowerlineMainMenu`, `layoutPresetNames`, `filteredSkillCount`, `clearSegmentCache`, `motionIntervalMs`, `knownSettings`, `DEFAULT_WELCOME`, `getEffectivePreset`, `getAppearancePatches`, `isStoredValueValid`, `doctorRowsBySkill`, `LANTERN_HEIGHT`, `ALL_WELCOME_WIDGETS` were verified unreferenced across src, tests, scripts and docs. None were re-exported from `index.ts`; third-party deep-imports of these names will break — see this note if you consume `src/**` directly.

- **Usage accounting now bills everything the provider bills.** Tool-result `usage`, standalone `usage`/`compaction`/`branch_summary` session entries, and billed error/aborted assistant messages all count toward `token_in`/`token_out`/`token_total`/`cost` — previously only successful assistant messages did. Cache-hit percentages now include `cacheWrite` in the denominator (writes are prompt misses).
- **`cache_read` gains `request` and `session-request` formats**, showing the latest request's cache split (`4.2k 71%`) colored by hit rate: `cacheHit`/`cacheHitWarn`/`cacheHitError` semantic colors (green/amber/red at ≥70%/≥30%). The per-request value clears on compaction and model changes.


## [1.25.0] - 2026-11-12

### Added
- **Keyword paint on the powerline: the status line reacts to what you type.** Ported and re-architected from the x30 motion proposal on the old fork — where it ran its own 50 ms `setTimeout` next to the MotionScheduler, it now leases a `powerline-paint` consumer on the shared clock and drops the lease at idle, so an untouched session keeps its 0 FPS guarantee. Nine color-only styles (shimmer, rainbow, ember, heat, aurora, comet, prism, tide, pulse) recolor the composed line at render time, so layout width never shifts: a matched keyword (`ultrathink`, `think harder`, `lanternwake`, `wish`, …) paints a short burst then holds its accent while the draft still contains the word, thinking level selects the streaming look (`max`/`xhigh` → rainbow chase), and the last-prompt row highlights the matched span. Priority: keyword hold/burst > thinking level > streaming shimmer > idle none. `wishcraft.motion.enabled` and `wishcraft.motion.keywords` (both default on), `WISHCRAFT_REDUCED_MOTION`, `NO_COLOR`, and a non-`full` motion level all disable it.
- **The extension now activates cleanly under `pi --mode rpc`, with a host integration test to keep it that way.** `ctx.hasUI` is `true` in rpc mode, so every TUI-only call used to pass its gate and then die silently — or worse: `ctx.ui.custom()` returns `undefined` in rpc, and the welcome overlay's `.catch` on that `undefined` threw an uncaught TypeError on every rpc `session_start`. The session bootstrap now branches on `ctx.mode`: under `tui` nothing changes; under `rpc` the six powerline widgets are exported as `string[]` widget lines (the only form that crosses the rpc UI subprotocol), refreshed on the same scheduler cadence as a TUI repaint, and the welcome overlay degrades to a single `notify`. `tests/pi-host-rpc.test.ts` boots the real pi host over JSONL — LF-framed, both pipes drained — and asserts every slash command registers, the `powerline-*` widgets and statuses arrive as `extension_ui_request` records, and not a single non-JSON line ever reaches stdout. Diagnostics moved from `console.debug` (stdout — protocol corruption) to a `debugLog` helper on stderr.

## [1.24.0] - 2026-11-12

### Fixed
- **Git probes no longer race interactive git.** Every read-only `git` spawn (`src/git/status.ts`, `bash-mode/completion.ts`) now runs with `GIT_OPTIONAL_LOCKS=0` and `windowsHide: true`, so status polling can't refresh `.git/index` under a real checkout and orphaned `index.lock` files stop bricking the repo.
- **Think levels high/xhigh/max got their rainbow back.** The thinking segment collapsed all three into the plain `thinking` color; it now uses dedicated `thinkingHigh`/`thinkingXhigh`/`thinkingMax` semantic colors (default `rainbow`, overridable per preset — the `rainbow` ColorValue itself is new).
- **Token totals prefer the provider-reported `totalTokens`.** The four-field sum undercounted providers that report reasoning/other tokens only in the total.

## [1.23.0] - 2026-11-08

### Fixed
- **Releases reach npm again, with the token npm actually accepts.** Five tags — v1.18.0 through v1.22.0 — were cut but never published, so `npm install @groeponline/pi-wishcraft` still handed out 1.17.0 while the repository was at 1.22.0; the publish job of the v1.22.0 tag died with `ENEEDAUTH`. The pipeline assumed npm trusted publishing, and a probe run from this repository shows why that assumption was wrong: `id-token: write` is granted and the id token is present, but npm answers the OIDC token exchange for `@groeponline/pi-wishcraft` with **401**, so npmjs.com has no matching trusted publisher and npm fell back to "no credential at all". The `publish` job now carries the organisation `NPM_TOKEN` into `setup-node`'s `.npmrc` as `NODE_AUTH_TOKEN` (the probe confirms it authenticates as `chefgroeponline`), keeps `id-token: write` for the day the publisher is configured, and `RELEASE.md` records the measured state with the one-time npmjs.com steps to switch over. The version holes stay: npm versions need not be contiguous, so this is the first version on the registry since 1.17.0.
